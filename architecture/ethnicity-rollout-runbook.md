# Ethnicity Rollout Runbook

This runbook is for the legacy ethnicity remediation rollout in `proj-coach-backend`.

It assumes the backend code, regression tests, dry-run audit tooling, and staged reindex tooling are already merged or checked out locally.

## Preconditions

- Use a write-capable production MongoDB credential. The read-only analytics credential is not sufficient.
- Use a backend shell that already has valid production config access for MeiliSearch.
- Keep `SKIP_EXTERNAL_SERVICE_CONNECTIONS=1` for script-driven reindex runs so Redis/RabbitMQ/Slack/Loki are not required.
- Do not start the Meili reindex until the Mongo normalization write has completed successfully.

## Read-Only Artifacts

These files are generated by the dry-run tooling:

- `/tmp/ethnicity-audit.json`
- `/tmp/ethnicity-normalization-plan.json`
- `/tmp/ethnicity-reindex-plan.json`
- `/tmp/ethnicity-reindex-userid-chunks.json`

## Step 1: Mongo Normalization Write

Run the Mongo write against a write-capable primary URI:

```bash
MONGO_URI="mongodb+srv://<write-user>:<write-password>@prodcluster.pyr2ag.mongodb.net/ditto" \
bun run scripts/normalize-ethnicity-rollout-data.ts \
  --execute \
  --yes \
  --json /tmp/ethnicity-normalization-executed.json
```

Expected effect:

- normalize legacy/empty/alias `expectedEthnicity` values
- clear routine unresolved self ethnicity to `null`
- leave no residual manual-review queue under the current audit assumptions

## Step 2: Export Fresh Reindex Plan

Immediately regenerate the reindex candidate list after the Mongo write:

```bash
MONGO_URI="mongodb+srv://<write-user>:<write-password>@prodcluster.pyr2ag.mongodb.net/ditto" \
bun run scripts/export-ethnicity-reindex-plan.ts \
  --json /tmp/ethnicity-reindex-plan.json \
  --ids-json /tmp/ethnicity-reindex-userid-chunks.json
```

## Step 3: Staged Meili Reindex

Dry-run a single chunk first:

```bash
SKIP_EXTERNAL_SERVICE_CONNECTIONS=1 \
bun run scripts/reindex-ethnicity-users.ts \
  --ids-json /tmp/ethnicity-reindex-userid-chunks.json \
  --chunk-index 0
```

Execute a bounded chunk range:

```bash
SKIP_EXTERNAL_SERVICE_CONNECTIONS=1 \
bun run scripts/reindex-ethnicity-users.ts \
  --ids-json /tmp/ethnicity-reindex-userid-chunks.json \
  --from-chunk 0 \
  --to-chunk 9 \
  --execute \
  --json /tmp/ethnicity-reindex-run-0-9.json
```

Repeat until all chunks are complete.

## Step 4: Fresh Post-Write Audit

Rerun both read-only checks after Mongo + Meili are complete:

```bash
MONGO_URI="mongodb+srv://<write-user>:<write-password>@prodcluster.pyr2ag.mongodb.net/ditto?readPreference=secondary&readPreferenceTags=nodeType:ANALYTICS" \
bun run scripts/audit-ethnicity-proof.ts \
  --json /tmp/ethnicity-audit-post-write.json
```

```bash
MONGO_URI="mongodb+srv://<write-user>:<write-password>@prodcluster.pyr2ag.mongodb.net/ditto?readPreference=secondary&readPreferenceTags=nodeType:ANALYTICS" \
bun run scripts/normalize-ethnicity-rollout-data.ts \
  --json /tmp/ethnicity-normalization-post-write.json
```

Expected post-write outcomes:

- normalization candidates collapse to zero or near-zero
- residual manual-review queues remain zero
- reindex candidate list collapses to zero or to an explainable residual tail if writes were partial

## Step 4b: Profile Integrity Audit / Repair

Run the profile integrity audit to confirm there are no orphan or duplicate
`user_profiles` rows left behind by the rollout work:

```bash
MONGO_URI="mongodb+srv://<write-user>:<write-password>@prodcluster.pyr2ag.mongodb.net/ditto" \
MONGO_DB="ditto" \
bun run scripts/audit-profile-integrity.ts \
  --json /tmp/profile-integrity.json
```

If orphan rows exist, clean them up first:

```bash
MONGO_URI="mongodb+srv://<write-user>:<write-password>@prodcluster.pyr2ag.mongodb.net/ditto" \
MONGO_DB="ditto" \
bun run scripts/cleanup-orphan-profiles.ts \
  --execute \
  --json /tmp/orphan-cleanup.json
```

If duplicate rows exist, remove only the stale duplicates while keeping the newest
profile row per user:

```bash
MONGO_URI="mongodb+srv://<write-user>:<write-password>@prodcluster.pyr2ag.mongodb.net/ditto" \
MONGO_DB="ditto" \
bun run scripts/cleanup-duplicate-profiles.ts \
  --execute \
  --json /tmp/duplicate-profile-cleanup.json
```

Then verify/repair the `user_profiles.userId` unique index:

```bash
MONGO_URI="mongodb+srv://<write-user>:<write-password>@prodcluster.pyr2ag.mongodb.net/ditto" \
MONGO_DB="ditto" \
bun run scripts/check-profile-indexes.ts \
  --json /tmp/profile-indexes.json
```

```bash
MONGO_URI="mongodb+srv://<write-user>:<write-password>@prodcluster.pyr2ag.mongodb.net/ditto" \
MONGO_DB="ditto" \
bun run scripts/enforce-profile-userid-unique-index.ts \
  --execute \
  --json /tmp/profile-userid-index-repair.json
```

Expected integrity outcomes:

- orphan `user_profiles` rows = `0`
- duplicate `user_profiles` rows = `0`
- `user_profiles.userId` unique index present and enforced

## Step 6: Manual Smoke Checklist

These are the non-automated checks that still matter after the test suite passes:

- In `proj-coach-app`, confirm onboarding shows no self-ethnicity `Prefer not to say` option and does show `No Preference` for expected ethnicity.
- In `proj-coach-app`, confirm a user with unresolved self ethnicity still renders a clean basic-profile summary.
- In `ditto-internal-frontend`, open the operator profile edit dialog and verify self ethnicity can be cleared to blank while expected ethnicity still requires an explicit choice.
- In `ditto-internal-frontend`, run matchmaker autofill for:
  - unresolved self ethnicity + constrained expected ethnicity
  - concrete self ethnicity + expected `No Preference`
- In `ditto-internal-frontend`, open the matching graph and confirm normalized `White` users still color correctly.
- In `prompt-manager-backend`, confirm prompt/editor autofill does not reintroduce legacy ethnicity sentinel values in generated filters.

After deploy, compare these against the saved pre-rollout baseline:

## Rollback Notes

- The Mongo normalization script is a one-way data cleanup. There is no automatic rollback script.
- Before running Step 1, ensure there is a durable export or snapshot strategy for the affected `user_profiles` documents if rollback is required.
- The Meili reindex is safe to rerun; it is derived state.

## Verification Notes

- Keep the current regression suites green before and after rollout.
- Compare pre/post audit counts, especially:
  - total reindex candidates
  - active eligible expected backfills
  - active eligible self clears
  - source users with ethnicity-only candidate deltas
